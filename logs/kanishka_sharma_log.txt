PART D - HOW TO RUN AND TEST MY PART  (for the whole team)
#############################################################################
1. Pull the branch. In backend/ run:  npm install
2. Copy backend/.env.example to backend/.env and fill the values.
   IMPORTANT: JWT_SECRET is now REQUIRED. Without it POST /api/auth/login
   answers "Server authentication configuration is missing." for EVERYONE.
3. Load schema.sql in MySQL (as before).
4. Optional demo data:   cd backend && node scripts/seedAgentDemo.js
5. Start backend:        cd backend && npm run dev          (http://localhost:5000)
6. Start frontend:       cd frontend && npm run dev         (http://localhost:3000)
7. Open http://localhost:3000/agent-kani
   Demo agent login:     kanishka.agent@hts.local  /  Agent@123
   Demo requester login: demo.requester@hts.local  /  Requester@123
8. Automated API checks (no MySQL needed):  cd backend && npm run test:agent
9. Optional: frontend/.env.local with NEXT_PUBLIC_API_URL=http://localhost:5000
   (that is already the default).

Manual test path: login -> Team Queue -> Claim ticket -> open it -> New -> Open ->
In Progress -> add public reply and private note -> On Hold -> back to In Progress ->
Resolved (solution message) -> Create Knowledge Base draft -> Publish.

#############################################################################
PART E - API REFERENCE  (all need header  Authorization: Bearer <token>  and Agent role)
#############################################################################
POST /api/auth/login                      { email, password } -> { message, token, user }  (token valid 1 hour)

Base URL: /api/agent
GET    /me                                my profile and team
GET    /tickets?scope=mine|team           queue (mine = assigned to me, team = unassigned in my team)
POST   /tickets                           raise on behalf: { requester_email, subject, description,
                                          category_id, priority, channel: Phone|Walk-in }
GET    /tickets/:id                       { ticket, comments, attachments, history, permissions }
POST   /tickets/:id/claim                 assign an unassigned team ticket to me (New -> Open)
POST   /tickets/:id/release               give a New/Open ticket back to the team
POST   /tickets/:id/comments              { body, is_internal }
PATCH  /tickets/:id/status                { status, note }   note required for Resolved
PATCH  /tickets/:id/priority              { priority, reason }
POST   /tickets/:id/kb-draft              resolved ticket -> draft KB article
GET    /attachments/:id/download          file download
GET    /notifications                     { unread_count, items }
POST   /notifications/read                { id } for one, empty body for all
GET    /categories
GET    /kb?scope=mine|published           POST /kb   { title, content, category_id, status }
GET    /kb/:id                            PUT /kb/:id  (own articles only)
Also kept: GET /api/tickets/assigned (my first endpoint, same data as scope=mine).

Allowed agent status changes (SRS 7.3):
  New -> Open | Open -> In Progress | In Progress -> On Hold or Resolved |
  On Hold -> In Progress | Reopened -> In Progress.
  Closing and reopening are done by the requester / the 7-day auto-close job.
